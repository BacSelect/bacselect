## Failure

Array tasks 001–004 ran on `kscprod-bio2.esr.cri.nz`.

Each first network attempt failed while NCBI Datasets posted to the genome
`dataset_report` API. The client reported a TCP connection reset after its own
internal retry attempts. No dehydrated ZIP was created.

No batch reached hydration or sequence validation.

## Retry-state defect

The original Slurm wrapper treated any existing `.partial` directory as
resumable. After a pre-ZIP network failure, subsequent whole-batch attempts
therefore called the worker with `--resume`, which correctly failed because
`dehydrated.zip` did not exist.

The first execution consequently provided one real network attempt for each
affected batch rather than three.

## Node isolation

A one-accession request using the frozen NCBI Datasets 18.35.0 environment and
the same acquisition command failed on `kscprod-bio2` with the same connection
reset.

The corresponding request succeeded on `kscprod-bio8`.

A subsequent production-shaped test ran two concurrent 500-accession
dehydrated requests on `kscprod-bio8`. Both completed successfully and both ZIP
archives passed integrity testing.

This supports an operational node/network-path failure. It does not support
changing the frozen target set, batch size, concurrency, Datasets version, or
acquisition arguments.

## Prospective correction

The replacement execution keeps the same 15,326 targets, 31 frozen batches,
500-accession batch size, final batch size 326, array concurrency `1-31%2`,
Datasets 18.35.0, and frozen acquisition command.

Two operational changes are made:

1. the array is pinned to `kscprod-bio8`;
2. a recorded failed pre-ZIP download is archived intact before the next
   whole-batch attempt starts fresh.

A partial directory is automatically resumed only when it contains the
completed dehydrated ZIP, hydrated package directory, attempt origin, and
accession list. Unexpected partial states fail closed.

The failed `b172cd1` run is not reused as scientific sequence input.
